# GPT 顾问与 Hermes 开发工作流

## 角色分工

GPT 负责：

- 确定当前最小目标和暂不处理的范围；
- 审查架构边界、风险和验收标准；
- 把大型需求拆成单个纵向功能；
- 根据测试、差异和实际试玩证据验收。

Hermes 负责：

- 在本地读取仓库和允许访问的资料；
- 先分析相关数据流，再修改代码；
- 实现当前功能、测试和文档；
- 执行完整验证并更新项目交接文件；
- 报告变更、证据、风险和下一建议。

模型输出、小说提取结果和玩家输入都不可信，必须经过显式校验。任何 Agent
都不得直接用自然语言输出修改玩家状态。

## 每次任务的起点

Hermes 应按顺序阅读：

1. `AGENTS.md`
2. `PROJECT_STATE.md`
3. `NEXT_TASK.md`
4. `CHANGELOG.md` 的 `Unreleased`
5. 相关模块、测试和文档

若交接文件与实际代码或测试冲突，以仓库和当前验证为准，并修正交接文件。

## 可复制的任务模板

```text
请阅读 AGENTS.md 和项目交接文件，但先不要修改代码。

目标：
实现一个版本化的本地存档与读取闭环。

请先说明：
1. 当前相关文件和数据流；
2. 拟修改文件；
3. 明确不修改的模块；
4. 状态一致性和向后兼容风险；
5. 场景测试与 CLI 冒烟方案。

限制：
- 不引入第三方依赖；
- 不修改战斗公式；
- 不添加网络或账号系统；
- 不进行无关重构；
- 所有实体仍使用稳定 ID；
- 私有小说目录只读且不得提交。

确认分析与目标一致后再执行。完成前运行：
python -m unittest discover -s tests -v
python scripts/check_repo_safety.py
```

## 合适的纵向任务

- 保存并读取一次完整游戏状态；
- 使用一种消耗品并验证库存变化；
- 装备一件武器并影响一次确定性战斗；
- 完成一条只有一个条件的原创任务；
- 增加独立的内容包校验 CLI；
- 为拆章脚本增加一种明确的标题格式。

不合适的单次任务：

- 同时制作职业、技能、装备、任务和经济系统；
- 在没有存档版本设计时引入数据库；
- 在确定性规则未稳定时加入 LLM 自由行动；
- 让多个子 Agent 各自决定永久实体 ID；
- 为“以后可能需要”而引入微服务、消息队列或向量数据库。

## 验收证据

每次交付至少应包括：

- 修改文件与行为影响；
- 新增或更新的场景测试；
- 完整测试命令和通过数量；
- 仓库安全检查结果；
- 一次与功能对应的实际 CLI 冒烟过程；
- 已知限制；
- 更新后的四个项目交接文件。

GPT 应针对证据审查，而不是只接受“已经完成”的文字结论。
